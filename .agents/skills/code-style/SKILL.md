# 代码风格规范

在 familytree 仓库内写代码时遵循以下规范。仓库架构与领域约定见 [familytree skill](../familytree/SKILL.md)；本文件只管代码长什么样。

## 1. 不重复、不冗余

- **单一实现**：同一逻辑只允许存在一份。写新功能前先搜是否已有等价实现（后端 `people/`、`auth/`、`database/`；前端 `lib/`、`stores/`、`api/`、`components/`）。年龄只在 `server/src/people/age.ts`。亲子角色文案只在 `ROLE_LABELS`，性别文案只在 `SEX_LABELS`。
- **相似代码超过 3 处才抽象**；2 处相似允许重复，宁要两段直白代码也不要一个牵强的抽象。
- **不留临时代码**：调试用 `console.log`、注释掉的旧代码、`TODO`/`FIXME` 残留、只为先跑通的绕路逻辑，提交前必须清掉或转成正式实现。
- **不留死代码**：未被引用的函数、类型、常量、路由、样式一并删除。需要时从 git 历史找回。
- **不加无用防御**：不为不可能发生的情况写分支。信任项目内的类型契约与调用约定。对外的 HTTP 正文和数据库约束仍要校验。

## 2. 现代语言风格

**TypeScript（后端 NestJS 与前端 Vue）**

- `const` 优先、箭头函数、模板字符串、可选链 `?.` 与空值合并 `??`；`async/await` 而非 `.then` 链。
- 类型从使用处推导，避免冗余显式标注。导出的数据结构用 `interface`。联合字面量优于 `enum`：性别是 `'male' | 'female'`，亲子角色是 `PARENT_ROLES` 推出的 `ParentRole`。
- 不用 `any`。确需逃逸时用 `unknown` 再收窄。不写 `!` 非空断言，除非紧邻的代码已经证明非空。
- 空字符串在写入数据库前收成 `null`（已有 `blank`）。不要同时用空字符串和 `null` 表示「没有」。
- 组件一律 `<script setup lang="ts">`。可复用的纯计算放 `lib/`，跨页面状态放 Pinia store，不把请求散落在组件里。
- 数组处理用 `map` / `filter` / `find` / `some` / `flatMap`。查找不要写 `filter(...)[0]`。建索引用 `new Map`。不可变更新用展开，不直接改入参或 store 里的数组。
- 后端结构化数据用实体和 DTO，不用裸对象在层与层之间传一串看不懂的字段。JSON 边界保持现有的 camelCase。

**通用**

- 使用当前语言的主流写法，不用上一代惯例（`var`、`function` 回调、`Array<T>` 可写成 `T[]` 时仍保持与周围文件一致）。
- 一次改动内风格与所在文件统一。

## 3. 简练、优雅

- **先想清楚再写**：能用一段直白代码解决的，不引入基类、回调参数或配置项。
- **禁止过度设计**：不为以后可能预留参数、钩子、泛型。本仓库没有角色权限、没有多租户、没有「主家族」字段，不要顺手加上。
- **早返回**：先处理边界与错误，主逻辑不留缩进金字塔。嵌套不超过 2–3 层。
- **命名表意**：名字说清是什么、做什么。函数名用动词，布尔用 `is` / `has` 或 `deceased` 这类已有词。避免 `data2`、`tmp`、`flag`。
- **注释只写为什么**：解释业务口径、布局重排、外部约束。代码已经表达的步骤不要再注释一遍。
- **删比加好**：修改时优先考虑能否删掉代码达到目的。

## 4. 规模控制

| 对象 | 上限 | 超限处理 |
|------|------|----------|
| 单文件 | 约 300 行 | 按职责拆到同目录。领域文件优先扁平，复杂了再分子文件 |
| 单函数 | 约 50 行 | 抽出内聚的私有函数，命名即注释 |
| 单个 Vue `<script>` | 约 250 行 | 计算放 `lib/`，请求放 store |
| 函数参数 | ≤ 4 个 | 更多则收成参数对象 |
| 嵌套深度 | ≤ 3 层 | 早返回、提取函数 |

- 拆分标准是职责单一，不是机械行数。一个函数做一件事。
- `layout.ts` 已经接近上限。再加规则时抽出纯函数，不要把 Vue Flow 的节点拼装写进布局。

## 5. 改动边界

- 只改与任务相关的代码。发现邻近问题可以修，但保持 diff 聚焦，不做无谓的重排、重命名、重格式化。
- 触碰到的旧代码若违反本规范，鼓励小范围顺手修正。大规模重写应当是独立任务。
- 新增功能先遵循 [familytree skill](../familytree/SKILL.md) 的修改导航。风格规范不覆盖分层和数据契约。

## 6. 测试代码

测试与业务代码遵守同一套规范，另有：

- **不留过时测试**：行为变更时同步改断言。不允许改生产代码去迁就旧断言。
- **不留僵尸用例**：跳过的用例必须写明原因。永远为真的断言视为死代码。
- **不镜像实现**：断言行为和契约（根是谁、状态码、`error` 文案、`age`），不把生产算法复述一遍再比对。
- **位置**：后端只放 `server/test/`，前端只放 `web/test/`。见 [AGENTS.md](../../AGENTS.md)。
- **命名表意**：`keeps a childless spouse beside the person who has the descendants` 这类句子说清场景和期望。
- **后端 HTTP 测试**用临时 SQLite，不碰 `server/data/dev.sqlite` 或 `docker/sqlitefile/`。

## 7. 提交前自检

- [ ] 没有复制出来的第二份实现；`console.log` 已清除
- [ ] 没有注释掉的代码块、未引用的死代码
- [ ] 没有为假设性需求预留的参数、分支、抽象
- [ ] 新代码用的是项目当前的风格
- [ ] 文件和函数规模在限额内
- [ ] 测试与本次改动同步，并按 [AGENTS.md](../../AGENTS.md) 真正执行过
