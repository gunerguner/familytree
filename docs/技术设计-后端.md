# 百忍堂张氏族谱 — 后端设计

整体形态、选型和 Docker 见 [技术设计.md](./技术设计.md)。本文是 NestJS 工程里要落地的数据、接口和推算规则。

人物表里没有锚点、家族名或「主根」标记。谁是根，由「没有父母，并且前端不把他画成配偶侧卡」决定。张尔寿只是种子数据里的一个人。

## 1. 工程

在仓库里生成：

```text
npx @nestjs/cli new server --package-manager npm --strict --skip-git
```

这条命令要在仓库根目录执行，才会用根上的 `.npmrc`。npm 源、better-sqlite3 预编译包、Node 头文件、Docker 与 Debian 源的国内地址见 [技术设计.md](./技术设计.md) 第 2.3 节。

语言选 TypeScript。生成后改成下面的模块，不保留示例里的 `AppController` 示例路由。HTTP 用默认的 Express 适配器。

```text
server/
  src/main.ts
  src/app.module.ts
  src/database/database.module.ts
  src/auth/                     # 账号、会话、守卫、限流
  src/people/                   # 人物、关系、年龄、树
  src/people/age.ts
  src/people/age.spec.ts
  src/health/health.controller.ts
  src/seed/seed.service.ts
  src/backup.ts                 # node dist/backup.js
  src/reset-password.ts
  seed/family.json
```

`main.ts` 在 `listen` 之前完成数据库打开、迁移、引导账号和种子。全局管道使用 `ValidationPipe`，`whitelist: true`。全局守卫检查会话；健康检查、登录、退出标成公开。变更方法再检查请求头 `X-Familytree`。

静态文件用 `@nestjs/serve-static`。`STATIC_DIR` 有值时，先匹配磁盘文件，匹配不到且路径不是 `/api` 时返回 `index.html`。开发环境不设 `STATIC_DIR`，页面由 Vite 提供。

开发端口写在 `PORT`，默认 `3000`，与 Vite 代理一致。生产镜像把 `PORT` 设为 `8080`。

## 2. 数据库

用 better-sqlite3 打开 `DATABASE_PATH`。连接建立后立刻执行：

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;
```

TypeORM 使用 `better-sqlite3` 驱动，`migrationsRun` 不靠 CLI 手工执行，由启动代码调用 `dataSource.runMigrations()`。时间列用 RFC3339 文本，时区为 `Asia/Shanghai`。

下面的 DDL 是第一份迁移要得到的结构。

### 2.1 人物

```sql
CREATE TABLE persons (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  name         TEXT NOT NULL CHECK (length(trim(name)) > 0),
  kinship      TEXT,
  former_name  TEXT,
  nickname     TEXT,
  birth_text   TEXT,
  death_text   TEXT,
  narrative    TEXT,
  created_at   TEXT NOT NULL,
  updated_at   TEXT NOT NULL
);
```

空字符串在写入前改成 `NULL`。没有表示「这是主根」的列。

### 2.2 亲子

```sql
CREATE TABLE parent_links (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  child_id    INTEGER NOT NULL REFERENCES persons(id),
  parent_id   INTEGER NOT NULL REFERENCES persons(id),
  role        TEXT NOT NULL CHECK (
                role IN (
                  'father',
                  'stepfather',
                  'mother',
                  'stepmother',
                  'adoptive_mother',
                  'adoptive_father'
                )
              ),
  sort_order  INTEGER NOT NULL DEFAULT 0,
  CHECK (child_id <> parent_id),
  UNIQUE (child_id, parent_id)
);

CREATE INDEX parent_links_parent ON parent_links(parent_id);
CREATE INDEX parent_links_child ON parent_links(child_id);
```

| role | 文案 |
| --- | --- |
| `father` | 父亲 |
| `stepfather` | 继父 |
| `mother` | 母亲 |
| `stepmother` | 继母 |
| `adoptive_mother` | 养母 |
| `adoptive_father` | 养父 |

同一对父母名下的子女顺序，优先用生父那条链接的 `sort_order`；没有生父时用继父；再没有则用母亲、继母或养母那条。服务在写入时把这个子女的全部亲子链接写成同一个 `sort_order`。

### 2.3 配偶

```sql
CREATE TABLE marriages (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  a_id        INTEGER NOT NULL REFERENCES persons(id),
  b_id        INTEGER NOT NULL REFERENCES persons(id),
  label       TEXT,
  sort_order  INTEGER NOT NULL DEFAULT 0,
  lo          INTEGER GENERATED ALWAYS AS (
                CASE WHEN a_id < b_id THEN a_id ELSE b_id END
              ) STORED,
  hi          INTEGER GENERATED ALWAYS AS (
                CASE WHEN a_id < b_id THEN b_id ELSE a_id END
              ) STORED,
  CHECK (a_id <> b_id),
  UNIQUE (lo, hi)
);

CREATE INDEX marriages_a ON marriages(a_id);
CREATE INDEX marriages_b ON marriages(b_id);
```

`label` 是这段婚姻的身份原文，两边的详情都显示同一句。`sort_order` 决定画在主卡片右侧时的左右顺序，小的在左。

### 2.4 账号与会话

```sql
CREATE TABLE accounts (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  username       TEXT NOT NULL UNIQUE,
  password_hash  TEXT NOT NULL,
  created_at     TEXT NOT NULL
);

CREATE TABLE sessions (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id   INTEGER NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  token_hash   TEXT NOT NULL UNIQUE,
  expires_at   TEXT NOT NULL,
  created_at   TEXT NOT NULL
);

CREATE INDEX sessions_account ON sessions(account_id);
```

`token_hash` 是 Cookie 里随机数的 SHA-256 十六进制。随机数是 32 字节，用 `crypto.randomBytes`。

密码散列格式：`scrypt$16384$8$1$<salt 的 base64url>$<hash 的 base64url>`。`crypto.scrypt` 的参数是 `N=16384`、`r=8`、`p=1`，盐 16 字节，输出 32 字节。校验用 `crypto.timingSafeEqual`。

## 3. 年龄

`src/people/age.ts` 是唯一的实现。前端不解析生卒原文。

输入是出生原文、卒于原文，以及「今天」（上海时区的日期）。输出：

| 字段 | 含义 |
| --- | --- |
| `birthYear` | 能读出的公历年，否则 `null` |
| `deceased` | 卒于原文去掉空白后还有字 |
| `age` | 按下面的规则得到的整数岁，否则 `null` |

### 3.1 怎样才算读出公历年

在原文里找第一个独立的四位年份，范围 `1800`–`2099`。`1900.2.18`、`1945 年`、`1868年8月12日` 都能读出年份。`正月十九`、`十一月初八`、`五月十八卯时` 读不出。

### 3.2 月日什么时候参与周岁

只有整段原文都不含农历特征时，才继续认月日。农历特征包括：`正月`、`腊月`、`冬月`、`闰月`、`初`、`廿`、`卅`，以及地支加「时」（子丑寅卯辰巳午未申酉戌亥）。

不含这些字时，用下面两种写法提取月和日：

- `YYYY年M月D日`，M、D 为阿拉伯数字
- `YYYY.M.D`、`YYYY-M-D`、`YYYY/M/D`

月必须在 1–12，日必须是该月存在的日子。对不上时丢掉月日，只留年份，年龄仍按年份差计算。

含农历特征时，即使旁边写了公历年，也不把农历月日当成公历去做生日折算。第一版不做历法换算。

一段原文里有两个四位年份时，取第一个。种子阶段就保存最终能辨认的那一版文字。

### 3.3 岁数

已卒时，结束日期来自卒于：月日齐全则用那个公历日，否则只用年份做减法。在世时，结束日期是今天：出生月日齐全则按周岁相对今天计算，否则用今年减出生年。

- 出生读不出年份：`age` 为 `null`。
- 已卒但卒于读不出年份：`age` 为 `null`。`deceased` 仍按原文是否有字来定。
- 两边参与计算的月日都齐全：`年龄 = 结束年 − 出生年`；若结束的月日早于出生的月日，再减 1。
- 其余能读出所需年份的情况：`年龄 = 结束年 − 出生年`。
- 结果小于 0 时 `age` 为 `null`。0 要返回。

JSON 里这三个字段始终出现，空值写 `null`，不要省掉键。

### 3.4 测试用例

今天固定为 2026-11-25：

| 出生 | 卒于 | age | birthYear | deceased |
| --- | --- | --- | --- | --- |
| `1900.2.18` | `1963.4.7` | 63 | 1900 | true |
| `1945 年` | 空 | 81 | 1945 | false |
| `1868年8月12日` | `1951年3月29日` | 82 | 1868 | true |
| `正月十九` | 空 | 空 | 空 | false |
| `十一月初八` | `四月十二` | 空 | 空 | true |
| `1958.4.7` | 空 | 68 | 1958 | false |
| `2020.12.1` | `2020.1.1` | 空 | 2020 | true |

`1868年8月12日` 到 `1951年3月29日`：尚未到 1951-08-12，所以是 82 岁。

## 4. 接口

基础路径 `/api`。除健康检查、登录、退出之外，都要有效会话。`POST`、`PATCH`、`DELETE` 还要请求头 `X-Familytree: 1`，否则 403，正文 `{"error":"缺少请求头"}`。

错误正文：

```json
{ "error": "给页面看的一句中文", "fields": { "name": "姓名不能为空" } }
```

没有字段错误时不带 `fields`。

| 状态 | 何时 |
| --- | --- |
| 400 | JSON 不合法，或角色不在枚举里 |
| 401 | 未登录，或登录失败 |
| 403 | 变更请求缺少 `X-Familytree` |
| 404 | 人物不存在 |
| 409 | 亲子关系成环 |
| 422 | 姓名为空、引用的人物不存在、指向自己、同一对配偶重复 |
| 429 | 登录过于频繁 |
| 503 | 健康检查时数据库不可用 |

### 4.1 健康检查

`GET /api/health`。成功 `200`：`{"ok":true}`。`SELECT 1` 失败则 `503`：`{"ok":false}`。

### 4.2 会话

Cookie 名 `familytree_session`。属性：`HttpOnly`、`SameSite=Lax`、`Path=/`。`COOKIE_SECURE=true` 时加 `Secure`。有效期与会话行一致，14 天。

Cookie 的值是 `base64url(随机 32 字节) + "." + hex(hmac)`。HMAC 的密钥是 `SESSION_SECRET`。入库的散列只覆盖前半段随机数。两段都通过、且会话未过期，才算登录。失败一律 401，不说明原因。

`POST /api/session`

```json
{ "username": "zhang", "password": "……" }
```

成功 `204`，`Set-Cookie`。失败 `401`，`{"error":"账号或密码不正确"}`。

同一账号已有会话时先删掉再发新的。10 分钟内同一 IP 失败 8 次，之后 `429`，`{"error":"稍后再试"}`。成功登录清掉该 IP 的计数。

`GET /api/session`：有效则 `200` `{"username":"zhang"}`，否则 `401`。

`DELETE /api/session`：删掉当前会话行，发出过期 Cookie。没有会话也返回 `204`。

取 IP 时，仅当直接连接来自回环地址或 `TRUSTED_PROXY` 时，才使用 `X-Forwarded-For` 最左侧一段。

### 4.3 整棵树

`GET /api/tree` 一次返回全部人物和关系，不按根分页，也不标哪一棵是主根。

```json
{
  "persons": [],
  "parents": [
    { "childId": 2, "parentId": 1, "role": "father", "sortOrder": 0 }
  ],
  "marriages": [
    { "id": 10, "aId": 1, "bId": 3, "label": "妻子", "sortOrder": 0 }
  ]
}
```

人物对象：

```json
{
  "id": 1,
  "name": "张尔寿",
  "kinship": "曾祖父",
  "formerName": null,
  "nickname": null,
  "birthText": "十一月初八",
  "deathText": "四月十二",
  "narrative": null,
  "birthYear": null,
  "deceased": true,
  "age": null
}
```

### 4.4 人物详情

`GET /api/persons/:id` 的 `person` 与上面相同，并带：

```json
{
  "parents": [{ "id": 1, "name": "张尔寿", "role": "father" }],
  "marriages": [{ "personId": 4, "name": "范氏", "label": "妻子", "sortOrder": 0 }],
  "children": [{ "id": 5, "name": "张伯森", "role": "father", "sortOrder": 0 }]
}
```

`children[].role` 是当前这个人在该链接上的角色。`parents[].role` 是对方的角色。

### 4.5 新增和修改

`POST /api/persons` 返回 `201`。`PATCH /api/persons/:id` 返回 `200`。正文都是详情。

```json
{
  "name": "张坚如",
  "kinship": "父",
  "formerName": "张坚",
  "nickname": null,
  "birthText": "1900.2.18",
  "deathText": "1963.4.7",
  "narrative": "经历原文\n\n备注原文",
  "parents": [{ "personId": 2, "role": "father", "sortOrder": 0 }],
  "marriages": [
    { "personId": 8, "label": "妻子", "sortOrder": 0 },
    { "personId": 9, "label": "继母", "sortOrder": 1 }
  ]
}
```

语义是整体替换这个人的字段、他作为子女的亲子链接，以及他参与的婚姻。父母可以是空数组，这时他若也不是别人的侧卡配偶，就会被画成一棵根。

校验：

- `name` 去掉两端空白后不能空。
- 父母、配偶的 `personId` 必须已存在，且不能是本人。
- 父母列表里同一个 `personId` 只能出现一次。婚姻同样。
- 两段婚姻若只是双方对调，视为同一段，返回 422。
- 替换亲子链接之后，从任何人沿父母向上不能走回自己。遇到环返回 409，`{"error":"这样会把祖先收成自己的后代"}`。

事务：更新人物行；删掉「他作为子女」的全部 `parent_links`；删掉他参与的全部 `marriages`；再插入新的。他作为别人父母的链接不动。

### 4.6 删除

`DELETE /api/persons/:id`，成功 `204`。任何人物都可以删，包括当前图上的根。

一个事务里：

1. 删除 `child_id` 或 `parent_id` 等于他的全部亲子链接。
2. 删除 `a_id` 或 `b_id` 等于他的全部婚姻。
3. 删除人物行。

不删除子女人物。子女若不再有父母，下一次 `GET /api/tree` 里他们仍然在，只是没有指向父母的链接。前端会把他们画成根。

## 5. 种子

`server/seed/family.json` 随镜像复制到 `/app/seed/family.json`。结构：

```json
{
  "persons": [
    {
      "key": "er-shou",
      "name": "张尔寿",
      "kinship": "曾祖父",
      "formerName": null,
      "nickname": null,
      "birthText": "十一月初八",
      "deathText": "四月十二",
      "narrative": null
    }
  ],
  "parents": [
    { "child": "bo-sen", "parent": "er-shou", "role": "father", "sortOrder": 0 }
  ],
  "marriages": [
    { "a": "er-shou", "b": "fan-shi", "label": "妻子", "sortOrder": 0 }
  ]
}
```

`key` 不入库。张尔寿这条不要写父母，这样他自然成为根。范氏只通过婚姻连到他，不写成另一个有子女的根。

启动时 `persons` 行数为 0 才灌，整份一个事务。失败则进程退出。

内容范围：

- 封面不产生人物。
- 世系图上每一个写了姓名的方框对应一个人。「……」不产生人。
- 说明表每一列对应一个人，与世系图姓名相同的合并。
- 经历、备注都有字时，记述为两段中间一个空行。
- 范氏若手写名能辨认为「范道悦」，写入 `nickname`，记述末尾加一行「说明表原名范氏，旁有手写修订」。
- 张坚如的 `formerName` 为「张坚」。
- 亲子和婚姻以世系图为准，再用说明表里的「继母」「续弦」「生母」校正角色。

以后要加另一姓，在页面上新建一个没有父母的人即可，不必改种子格式，也不必再跑这份 JSON。

## 6. 启动与命令

`main.ts` 顺序：打开数据库、迁移、引导账号、种子、再 `listen`。

引导账号：`accounts` 为空时读取 `BOOTSTRAP_USERNAME`、`BOOTSTRAP_PASSWORD`。任一为空，或用户名长度不在 1–32，或密码短于 8，进程退出。表里已有账号时忽略这两个变量。

`src/backup.ts`：调用 better-sqlite3 的 `backup()`，写到 `BACKUP_DIR`（默认 `/data/backups`）下的 `familytree-YYYYmmdd-HHMM.db`，并把路径写到标准输出。

`src/reset-password.ts`：读取 `RESET_USERNAME`、`RESET_PASSWORD`。账号不存在则以非 0 退出。存在则更新散列，并删除该账号的全部会话。

## 7. 配置

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `NODE_ENV` | 生产必填 | `production` |

| `BOOTSTRAP_PASSWORD` | 仅空库 | 至少 8 位 |

| `TRUSTED_PROXY` | 否 | 默认只信任 `127.0.0.1` |
| `TZ` | 镜像已设 | `Asia/Shanghai` |

## 8. 测试

用 Nest 的测试模块和独立的 SQLite 文件。至少覆盖：

- 未登录访问 `GET /api/tree` 得到 401；健康检查仍是 200。
- 错误密码 401，连续失败会 429。
- 登录后能取到树；退出后再取是 401。
- 新增一个没有父母的人之后，他出现在 `persons` 里，且没有任何 `parent_links`。
- 把祖先设成自己的子女得到 409，库内链接与提交前一致。
- 删除一个有子女的根之后，子女还在，且不再包含这条亲子链接。
- 第 3.4 节的代表值通过详情接口返回，`age` 没有时 JSON 为 `null`。
