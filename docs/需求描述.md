# 百忍堂张氏族谱 — 需求描述

## 1. 背景与目标

根据张其谊、严南提供的材料及口述，家族于二〇一八年六月整理成册《百忍堂 张》。现有资料是 `images` 目录中的照片：一页封面、一页世系图、五页《说明表》。照片之后的信息由张子敏修改。

本程序是一个需要登录的 Web 应用，用来浏览和续修族谱。第一份资料是《百忍堂 张》，程序本身不限于这一姓。以后可以再放入别的家族：没有父母的人就是一棵根，多棵根同时画在同一张图上。

- 用世系图的方式展示人物与亲缘，某个家族分支可以展开或折叠。
- 每个人可以查看说明表中的生平信息。
- 登录后可以增、删、改人物与关系，便于以后继续补充。
- 数据保存在后端的 SQLite 数据库中。照片是初始数据来源，不是运行时的展示介质。

## 2. 资料里有什么

说明表中有手写订正（例如范氏旁注「范道悦」、出生卒日期的手写覆盖）。入库时以能辨认的最终文字为准，并在备注中保留「原文有手写修订」这一事实，避免把涂改前的字当作另一条记录。

### 2.2 世系图在表达什么

世系图是父子（及配偶）结构，不是说明表那种「相对某一记述人的称谓」。图中能确认的主干如下。

- 顶端为张尔寿，配偶范氏（说明表称祖母；曾祖母为王夫人）。
- 张尔寿之下有两支：张伯森、张仲芬（说明表称祖叔父）。
- 张伯森一支：张坚如（原名张坚）。配偶周金秀、魏怀瑾（继母）。子辈为张其谊（配偶严南）、张其铮（配偶葛丽霞）。再往下是张予聪、张予凌、张予敏等及其配偶、子女。图中部分子女以「……」省略。
- 张仲芬一支：张勤如，配偶邱季珊、续弦印氏。子女包括榴官（嫁王家）、金元、达元、达达，以及贞宜（嫁周经胜）。榴官之下为王新、瑶芬。周经胜、贞宜之下为周侯廉（配偶张焕清）等，再下为周庆平、周佩玲、周庆刚、周庆伟、周兰兰及其配偶、子女。

因此系统里的树必须能表达：

- 一对父母（含生父、继父、生母、继母、续弦）与多个子女。
- 配偶可以有多位，并区分先后（前妻、继母、续弦）。
- 外嫁女儿及其夫家后裔（王家、周家）仍挂在本族树上。
- 图上用「……」表示的缺支，允许节点存在但子女不完整，不能为了画全树而编造人名。

### 2.3 说明表的列

每列一人，表头六项：

| 字段 | 照片中的实际写法 |
| --- | --- |
| 称谓 | 相对记述中心（主要为张其谊一系）的称呼：曾祖父、曾祖母、祖父、祖母、祖叔父、父、母、继母、大姑父、大姑母、兄、嫂、大侄、二侄、侄孙女、表兄、表弟、表姐、表姐夫、表嫂、表侄、表侄媳、表侄婿、表侄孙、大儿子、二儿子、儿媳、孙子、曾孙等。 |
| 姓名 | 本名。偶有原名（张坚如，原名张坚）、小名（瑶芬）。范氏有手写名「范道悦」。 |
| 出生（公、农历） | 很不统一。有公历 `1900.2.18`、农历「正月十九」「十一月初八」、只写到年（`1945 年`）、写到日时（「五月十八卯时」「正月二十二 十戌时」），有的括号里再注钟点（5–7 点、19–21 点）。 |
| 卒于（公、农历） | 同样混用公历与农历，有的带地点，如「静安区中心医院」。在世者此列为空。 |
| 经历 | 职业、求学、退休单位。如南通交行、武汉震寰纱厂、工人、运动领导者；上海无线电三厂、民立中学、上海造币厂、颐达信息技术等。 |
| 备注 | 关系说明（「是周庆平的妻子」「是其铮、其谊生母」）、籍贯与住址、离异、收养（「是周幼贞所生，是周侯廉、周经胜领养」）、附件编号（附件 1、附件 2、附件 3）、出生地（上海、韩国首尔）。 |

空列很多。姓名以外的项都可以缺。称谓是记述人口径，同一个人换一个观察点就会变，所以称谓不能代替父子关系。

照片里经历和备注分列。程序里合成一项「记述」：两列都有文字时一并写入，中间空一行；只有一列时只写入该列。不再分成两个字段编辑或展示。

## 3. 谁在用

家族内部使用，数据不对外公开。

- 未登录者只能看到登录页。
- 登录后可以浏览全树、展开折叠、查看人物详情。
- 登录后可以新增、修改、删除人物及其关系与生平。当前不区分「只读账号」和「编辑账号」；若以后要分权，再增加角色。

## 4. 功能需求

### 4.1 登录

- 提供登录页。账号与密码校验通过后进入族谱页，未通过时停留在登录页并提示失败。
- 登录状态在浏览器里保持，刷新后不必立刻重新登录；退出后回到登录页，且不能再打开族谱数据。
- 密码只以不可逆的形式存放，不明文写入数据库。

### 4.2 家族树

- 同一张画布上画出全部根。没有父母、并且不是画在别人身侧的配偶，各自成一棵根，横向并排、顶部对齐。第一份资料里的根是张尔寿。之后新增一个没有父母的人，他就成为新的根，出现在同一张图上，不必换成另一页。
- 用连线表示父母—子女。配偶显示在对应人物旁边，不单独占一代，也不因为没有父母就再占一棵根。
- 任一人物的后代可以整支折叠或展开。折叠后该节点仍在，其子孙隐藏；再次展开恢复。别的根不受影响。
- 树上至少显示姓名。出生年、是否已卒可以作为辅助信息。能算出年龄时，年龄也可以标在节点上；算不出则不占位置。节点里不放整段记述。
- 人物较多时可以平移、缩放，折叠某一支后画布不必留出大片空白。
- 点击人物打开详情，而不是只在树上展开长文。

### 4.3 人物详情

详情对应说明表里的称谓、姓名、生卒和记述，并补上画树所必需的关系：

- 称谓、姓名、原名或小名（有则显示）
- 出生、卒于（保留资料中的原文，不强制换成单一公历）
- 年龄（仅在能够计算时显示，规则见下）
- 记述（照片中的经历与备注合并为一段）
- 父母、配偶、子女（由关系生成，可点进对应的人）

没有的项显示为空，不显示「未知」占位句。年龄算不出时，详情和树上都不出现年龄，也不显示「年龄不详」。

年龄不入库，打开页面时按出生、卒于原文推算：

- 已卒：出生和卒于都能读出公历年份时才显示。月日也齐全时按周岁（卒日早于当年生日则减 1 岁）；只有年份时按卒年减生年显示。
- 在世（卒于为空）：出生能读出公历年份时，用同一规则相对今天计算。只有年份、没有月日时，按当前年减出生年显示。
- 只有农历而没有可确定的公历年份、只有月日没有年份、或原文无法解析出年份时，不显示年龄。

### 4.4 增删改

- 新增人物：至少填写姓名。称谓、出生、卒于、记述可空。同时指定父母和配偶；父母、配偶可以暂时不填，以便先记下图上关系尚未理清的人。
- 修改人物：可改上述字段，也可改父母、配偶。改父母后，树的位置跟着变。
- 删除人物：删除前提示会同时去掉他与父母、配偶、子女之间的关系。子女节点保留。子女若因此没有任何父母，就在同一张图上成为新的根，避免一次误删整支。任何人都可删除，包括某一棵的根。
- 配偶允许多个，并能标注顺序或身份（如生母、继母、继父、续弦、丈夫）。
- 保存后树上与详情立即一致。

### 4.5 初始数据

- 首次建立数据库时，装入照片中已能辨认的人物、说明表字段和世系关系。
- 装入范围限于七张照片里写明的内容。图上的「……」、未出现的附件 1–3、照片里读不清的字，不编造补全。
- 同一人只保留一条。世系图与说明表姓名对应得上的，合并为一人：树上的位置来自世系图，文字来自说明表。说明表中的经历与备注写入同一条记述。

## 5. 数据要求

SQLite 中需要能存住下面这些事实。

**人物**

- 姓名（必填）
- 称谓（资料原文，可空）
- 原名、小名（可空）
- 出生原文、卒于原文（可空，不拆碎农历时辰）
- 记述（可空，长文本；对应说明表的经历与备注）

**关系**

- 父母—子女：一个子女可记录父亲、母亲。父亲要能区分生父、继父、养父；母亲要能区分生母、继母、养母。
- 配偶：两人之间的婚姻，可有多段，可注明身份（前妻、续弦等）。
- 关系只连接已存在的人物。

**账号**

- 登录名与密码散列，供登录使用。

出生与卒于先按资料原文整段保存。公历、农历、时辰混写在同一格里，第一版不把整段日期改写成另一种历法。年龄只在上面的规则能从原文读出公历年份时显示，读不出则跳过。

## 6. 页面与风格

两个页面：登录页、族谱页。族谱页同时承担树、详情和编辑，不另做一套后台。

风格要求优雅、清新：

- 浅底、留白充足，文字用易读的中文衬线或黑体，标题克制。
- 树的节点像纸上的方框：细线、浅色填充，选中时再加重，不用大面积纯色块和高饱和装饰。
- 详情与编辑用同一套安静的面板，标签短、字段对齐。
- 页面标题用「族谱」。不把「百忍堂 张」写成程序名称；这一姓只是当前数据里的一棵根。第一版不为每棵根另设家族名称字段，靠根上的人物区分。

窄屏时仍要能登录、看详情和编辑。树在窄屏上允许横向滑动，不要求缩成一列卡片。

## 7. 第一版不做的事

- 不把照片嵌进页面当树使用。
- 不收录或展示附件 1、附件 2、附件 3（照片里只有编号，没有附件本身）。
- 不做公历农历互转、辈分自动生成、按姓名搜索、导出 PDF、多人同时编辑的冲突处理。
- 不开放注册。账号由部署时准备。
