# 百忍堂张氏族谱 — 技术设计

本文是整体设计，决定系统形态、技术选型和部署方式。接口、表结构和年龄算法在 [技术设计-后端.md](./技术设计-后端.md)。页面、组件和树的布局在 [技术设计-前端.md](./技术设计-前端.md)。功能范围以 [需求描述.md](./需求描述.md) 为准。

第一份资料是《百忍堂 张》。程序按多棵根来设计：没有父母、且不是别人身侧配偶的人，各自是一棵根，并排画在同一张图上。

## 1. 系统形态

一个给家族内部用的小型 Web 应用。人物从几十人起，以后可以加别的家族。读多写少，只有一个部署实例。

浏览器只打开一个站点。页面和 `/api` 由同一个 Node 进程提供，同源，不另设前端域名，也不做跨域。未登录时可以拿到登录页的静态文件，人物和关系只在登录后的接口里返回。

数据在一块 SQLite 文件里。生产环境只跑一个容器，数据库文件放在卷上。SQLite 不支持多个写入实例，部署时不要把这个服务扩成多副本。

```
浏览器
  │  HTTPS（宿主机上的反向代理）
  ▼
单个容器  familytree
  ├── NestJS：/api、登录 Cookie、静态页面
  ├── 年龄推算（只在读出时计算）
  └── SQLite  /data/familytree.db
```

宿主机用已有的 Nginx 或 Caddy 终止 TLS，反代到发布端口 `8084`（容器内仍监听 `8080`）。应用本身只监听 HTTP。同机还有其他站点时，外层边缘 Nginx 使用域名 `familytree.zhangzhicheng.info`。

## 2. 技术选型

| 层 | 选择 | 基线 |
| --- | --- | --- |
| 后端 | NestJS | 12，运行在 Node.js 22 的当前 LTS 补丁（至少 22.12） |
| HTTP | Nest 默认的 Express 适配器 | 与中文教程一致 |
| 数据 | TypeORM + better-sqlite3 | SQLite 文件 |
| 密码 | Node 自带的 `crypto.scrypt` | 不另装本地扩展 |
| 前端 | Vue 3.5、TypeScript、Vite 7、Vue Router 4、Pinia | 2026-11 的 Vue 稳定线是 3.5.45 |
| 组件 | Naive UI | 中文文档；表单、对话框、抽屉、下拉、按钮、消息 |
| 家族树 | 自写布局，HTML 卡片 + SVG 连线 | 多根并排；配偶在身侧 |
| 外部源 | 见第 2.3 节 | npm、预编译包、Node 发行包、Docker 镜像、Debian 软件源都写了国内地址 |
| 发布 | 多阶段 Docker 镜像，一个容器同时带页面和接口 | 见第 6 节 |

实现时把确切版本写进两边的 `package-lock.json`。

### 2.1 后端用 NestJS

选型要求是用户多、在国内安装和查资料都顺手。NestJS 是这一档里使用面最大的 Node 框架，中文文档、中文教程和现成示例都多，Express 适配器又和这些教程对得上。

同一档里比较过的做法：

- Midway 的中文文档完整，用户更多集中在阿里系项目，公开可查的排错经验少于 Nest。
- Fastify、Hono 更轻。登录、校验、模块划分要自己拼，不符合这次「用一套人多、国内好上手的框架」。
- 数据层用 TypeORM 加 better-sqlite3，因为这是 Nest 文档和中文教程的主流组合。不用 Prisma：它还要单独下载查询引擎二进制，国内网络经常失败。
- 密码用 `crypto.scrypt`。Argon2 的 npm 包装带本地扩展，和 better-sqlite3 叠在一起，本机构建更容易失败。scrypt 同样不可逆，参数写在后端设计里。

仓库根目录放 `.npmrc`，内容见第 2.3 节。认证自己做会话表和 HttpOnly Cookie，不用 JWT。退出登录要立刻失效。

### 2.2 前端用 Naive UI

Vue 4 在 2026 年 10 月仍处于规划，没有可安装的包。前端基线是 Vue 3.5。

组件不使用 Arco Design、Ant Design Vue 和 Vben。Element Plus 用户很多，默认外观和这三套同属中后台。需求要的是浅色、留白、纸面式的树，所以用 Naive UI：国内 Vue 3 项目里常用，中文文档完整，按钮、表单、对话框、抽屉、下拉和消息都有，主题可以把主色收成松绿、背景收成纸色。

族谱卡片和连线仍自己排。Naive UI 的树是缩进列表，组织架构组件也做不到「多棵根并排、配偶在身侧、按另一位父母分组」。这些控件不再手写。

`images/` 只在整理种子数据时由人阅读。运行中的站点不读取、不展示这些照片。

## 4. 领域对象

三件事实，对应需求里的人物、关系和账号。没有「锚点」或「主家族」字段。张尔寿只是种子里一棵根上的人。

**人物。** 姓名必填。称谓、原名、小名、出生原文、卒于原文、记述可空。记述是说明表里「经历」和「备注」合并后的一段文字。

**亲子。** 一条链接是「某个父母 — 某个子女 — 角色」。角色限于：父亲、继父、母亲、继母、养母、养父。同一对人物只有一条。子女可以暂时没有父母。没有父母的人，只要不是被画成配偶侧卡，就是一棵根。

**配偶。** 一段婚姻一行，带顺序和身份文字（妻子、续弦、丈夫等）。同一对人不重复建行。没有父母的配偶画在对方身侧，不另起一棵根。

**账号与会话。** 账号由部署时创建，没有注册接口。会话是随机令牌，库里只存散列。

年龄、公历年、是否已卒都不是列。读接口时按原文推算，算不出则返回空。

删除人物时，在一个事务里删掉他的亲子链接和婚姻，再删本人。子女保留。子女若不再有任何父母，下次画图时成为新的根，仍在同一张画布上。根也可以删除。

亲子关系不允许成环。配偶不参与成环判断。

兄弟、配偶的左右顺序用链接上的 `sort_order` 固定，以便和纸质世系图一致。这是实现字段，页面不把它做成单独的功能介绍；编辑表单里可以改这个整数。

## 5. 关键流程

### 5.1 登录

1. 打开站点，前端请求 `GET /api/session`。
2. 没有有效 Cookie 时得到 401，路由停在登录页。
3. 提交用户名和密码。成功则写入 Cookie，进入族谱页。失败停留登录页，提示「账号或密码不正确」，不区分是哪一项错了。
4. 刷新时 Cookie 还在，会话未过期，直接进入族谱页。
5. 退出调用 `DELETE /api/session`，删除会话行并清掉 Cookie。之后任何 `/api` 数据接口都是 401。

会话有效期 14 天，从登录时算起，中途不顺延。同一账号再次登录会删掉旧会话。

### 5.2 看树和改资料

1. 进入族谱页后请求一次 `GET /api/tree`，拿全量人物和关系。折叠只发生在浏览器里，不按分支另请求。
2. 前端把所有根排在同一张画布上。点击人物，路由变为 `/?person=<id>`，再请求 `GET /api/persons/<id>` 打开详情。刷新后仍打开这个人。
3. 新增一个没有父母的人并保存后，他作为新的根出现在同一张图上。
4. 新增、修改成功后，用返回的详情更新面板，并重新请求整棵树。
5. 删除前先确认。确认文案说明：会去掉他与父母、配偶、子女的关系，子女仍保留；没有父母的子女会成为新的根。成功后关闭面板并重新请求整棵树。

折叠状态记在 `localStorage`，键为 `familytree.collapsed`。换浏览器不会带走，这是视图偏好，不是族谱数据。

### 5.3 首次灌数

迁移执行完之后，若 `persons` 表是空的，读 `server/seed/family.json` 灌进去。表里已有人物时什么都不做，避免每次发布覆盖后来的修改。

种子只收录七张照片里能辨认的人和关系。世系图上的「……」、附件 1–3、读不清的字不补。同名对应得上的，树位置和说明表合成一条；经历与备注写入同一段记述，中间空一行。手写修订以最终能辨认的文字入库，记述末尾注明原文有手写修订。张尔寿在种子里没有父母，所以他是第一棵根，程序不把他标成特殊人物。

账号不在种子 JSON 里。`accounts` 为空时，用环境变量里的用户名和密码创建第一个账号。缺了其中任何一个，进程拒绝启动，避免带一个默认口令上线。

## 6. Docker 发布

### 6.1 镜像

多阶段构建。构建和运行都用 Node 22 的 Debian 镜像，保证 better-sqlite3 的二进制和运行环境一致。

1. `docker.m.daocloud.io/library/node:22-bookworm`：按 `.npmrc` 安装依赖，构建 `web/dist` 和 `server/dist`。对应官方镜像是 `docker.io/library/node:22-bookworm`。
2. `docker.m.daocloud.io/library/node:22-bookworm-slim`：放入生产依赖、`server/dist`、种子文件和 `web/dist`。安装 `curl` 前把 Debian 源换成阿里云。创建 uid `10001` 的 `app` 用户。

静态目录固定为 `/app/static`。数据库文件固定为 `/data/familytree.db`。进程监听 `8080`。

容器入口以 root 启动，只做两件事：创建 `/data`、`/data/backups` 并交给 uid `10001`，然后用 `setpriv` 降权运行 Node。卷第一次挂上来时是 root 所有，不降权前改所有者，应用会写不进 SQLite。

根文件系统只读。可写的只有数据卷和内存里的 `/tmp`。

```dockerfile
# docker/Dockerfile 的结构。构建上下文是仓库根。
# 官方镜像名为 docker.io/library/node:22-bookworm 与其 slim 版。
# 这里用 DaoCloud 的公开镜像前缀。DaoCloud 不可用时，改回官方名，
# 或在本机 /etc/docker/daemon.json 配置账号专属的阿里云 registry-mirrors。
ARG NODE_IMAGE=docker.m.daocloud.io/library/node:22-bookworm
ARG NODE_IMAGE_SLIM=docker.m.daocloud.io/library/node:22-bookworm-slim

FROM ${NODE_IMAGE} AS build
WORKDIR /src
COPY .npmrc ./
COPY server/package.json server/package-lock.json ./server/
COPY web/package.json web/package-lock.json ./web/
RUN npm ci --prefix server && npm ci --prefix web
COPY server ./server
COPY web ./web
RUN npm run build --prefix web && npm run build --prefix server
RUN npm ci --prefix server --omit=dev

FROM ${NODE_IMAGE_SLIM}
# bookworm 镜像的软件源在 debian.sources。换成阿里云后再装 util-linux（setpriv）。
# 备选主机名：mirrors.tuna.tsinghua.edu.cn
RUN if [ -f /etc/apt/sources.list.d/debian.sources ]; then \
      sed -i \
        -e 's|http://deb.debian.org/debian-security|https://mirrors.aliyun.com/debian-security|g' \
        -e 's|http://deb.debian.org/debian|https://mirrors.aliyun.com/debian|g' \
        -e 's|https://deb.debian.org/debian-security|https://mirrors.aliyun.com/debian-security|g' \
        -e 's|https://deb.debian.org/debian|https://mirrors.aliyun.com/debian|g' \
        /etc/apt/sources.list.d/debian.sources; \
    fi \
 && apt-get update \
 && apt-get install -y --no-install-recommends util-linux \
 && rm -rf /var/lib/apt/lists/* \
 && useradd --uid 10001 --create-home app
WORKDIR /app
COPY --from=build /src/server/node_modules ./node_modules
COPY --from=build /src/server/dist ./dist
COPY --from=build /src/server/seed ./seed
COPY --from=build /src/web/dist ./static
COPY docker/entrypoint.sh /usr/local/bin/entrypoint.sh
ENV STATIC_DIR=/app/static \
    DATABASE_PATH=/data/familytree.db \
    NODE_ENV=production \
    PORT=8080 \
    TZ=Asia/Shanghai
VOLUME /data
EXPOSE 8080
ENTRYPOINT ["/usr/local/bin/entrypoint.sh"]
CMD ["node", "dist/main.js"]
```

`entrypoint.sh`：

```sh
#!/bin/sh
set -eu
mkdir -p /data /data/backups
chown -R app:app /data
exec setpriv --reuid=app --regid=app --init-groups -- "$@"
```

### 6.2 编排

```yaml
# docker/docker-compose.yml
services:
  familytree:
    build:
      context: ..
      dockerfile: docker/Dockerfile
    image: familytree:local
    restart: unless-stopped
    ports:
      - "8084:8080"
    env_file: .env
    volumes:
      - ./sqlitefile:/data
    read_only: true
    tmpfs:
      - /tmp
```

`.env` 不进 git。`docker/.env.example` 列出变量名和空值。生产至少要有：

| 变量 | 作用 |
| --- | --- |
| `DATABASE_PATH` | `/data/familytree.db`。镜像里已设，一般不用改 |
| `SESSION_SECRET` | 给 Cookie 做 HMAC 的长随机串 |
| `BOOTSTRAP_USERNAME` | 仅在还没有任何账号时创建 |
| `BOOTSTRAP_PASSWORD` | 同上，明文只出现在环境变量里，入库的是 scrypt 散列 |
| `COOKIE_SECURE` | 经 HTTPS 反代对外时设为 `true` |

`TZ=Asia/Shanghai` 写在镜像里。在世者的年龄按中国日期的「今天」计算。

### 6.3 启动顺序

进程启动时按这个顺序做，全部成功才开始监听：

1. 用 better-sqlite3 打开数据库，执行 WAL、`busy_timeout` 和外键。
2. 执行尚未跑过的 TypeORM 迁移。
3. 若没有账号，用引导变量创建；变量不全则退出码非 0。
4. 若没有人物，灌入种子。
5. 监听 `0.0.0.0:8080`。

不在镜像构建阶段连数据库。

### 6.4 日志

不提供 `/api/health`，镜像也不做 `HEALTHCHECK`。进程能监听、首页能打开，即视为起来了。

日志打到标准输出，用 Nest 默认的 Logger。不写日志文件。登录失败可以记 IP 和用户名，不记密码，不记会话令牌。

### 6.5 备份

在线复制 SQLite 文件会抄到写了一半的 WAL。备份用 better-sqlite3 的 `backup()`，得到一个一致的单文件。

```text
docker compose exec -T -e BACKUP_DIR=/data/backups familytree \
  node dist/backup.js
```

命令把文件写到 `/data/backups/familytree-YYYYmmdd-HHMM.db`（上海时区），并把路径打到标准输出。备份文件留在卷里，不会自动删除。

恢复是停容器、用备份文件替换 `/data/familytree.db`、删掉残留的 `-wal` 和 `-shm`，再启动。

改密码：

```text
docker compose exec -T \
  -e RESET_USERNAME=... \
  -e RESET_PASSWORD=... \
  familytree node dist/reset-password.js
```

成功后删除该账号的全部会话。

### 6.6 反向代理

容器不要直接暴露到公网再补证书。宿主机反代示例（Caddy）：

```text
tree.example.com {
    reverse_proxy 127.0.0.1:8084
}
```

对外是 HTTPS 时，`COOKIE_SECURE=true`。应用只在取客户端 IP 做登录限流时读 `X-Forwarded-For` 的第一段，并且只信任本机反代。不要为了反代去开 CORS。

## 7. 安全边界

- 密码只存 scrypt 散列。
- 会话令牌只出现在 HttpOnly、`SameSite=Lax` 的 Cookie 里。开启 `COOKIE_SECURE` 后加上 `Secure`。
- 除登录、退出外，`/api` 都要有效会话。
- 变更类请求还要带自定义头 `X-Familytree: 1`。
- 登录失败按 IP 计数，10 分钟内超过 8 次返回 429。计数在进程内存里，单容器足够。
- 响应带 `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`X-Frame-Options: DENY`。
- 种子和备份都不包含密码。

## 8. 与需求的对应

| 需求 | 落点 |
| --- | --- |
| 多棵根在同一张图上，不限于张氏 | 无锚点字段；前端把所有根并排 |
| 登录后才能看族谱，刷新保持登录，退出即失效 | 服务端会话 + HttpOnly Cookie |
| 家族树、展开折叠、平移缩放 | 一次取全量，折叠和视口在前端 |
| 详情里的称谓、姓名、原名、小名、生卒、记述、亲属 | `GET /api/persons/:id` |
| 生卒够算才显示年龄 | 后端读出时推算，前端只展示数字 |
| 经历和备注合成记述 | 一列 `narrative` |
| 增删改；删人后子女还在，无父母者成为新根 | 事务内只删链接和本人 |
| SQLite | better-sqlite3 + 卷上的单文件 |
| 登录页和族谱页，控件用现成组件库 | Naive UI |

1. 用 Nest CLI 生成 `server/`，跑通迁移和会话。
2. 按后端设计建人物与关系，补年龄测试和《百忍堂 张》的种子。
3. 用 Vue 和 Naive UI 做登录页，以及能把多棵根排在同一张图上的树和详情。
4. 补上编辑和删除。删除一棵根之后，他的子女应作为新根留在同一张图上。
5. 按第 6 节做成镜像，从空卷启动，确认会自动迁移、创建账号、灌入种子，首页可打开。
