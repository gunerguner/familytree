# 百忍堂张氏族谱 — 前端设计

后端接口和年龄见 [技术设计-后端.md](./技术设计-后端.md)。本文描述浏览器里的工程、Naive UI 的用法，以及多棵根怎么排在同一张图上。

## 1. 工程基线

| 依赖 | 基线 |
| --- | --- |
| Vue | 3.5 稳定线。不使用尚未发布的 Vue 4，不使用 3.6 RC |
| 构建 | Vite 7、TypeScript 5、Node 22 |
| 路由 / 状态 | Vue Router 4、Pinia 当前稳定主版本 |
| 组件 | naive-ui |
| 测试 | Vitest，测布局纯函数 |

不安装 Arco Design、Ant Design Vue、Vben、Element Plus。族谱的卡片和连线不使用组织架构组件。

`vite.config.ts` 把 `/api` 代理到本机 Nest，开发端口以 `PORT` 为准，默认 `3000`。生产构建的 `base` 是 `/`，接口路径都写成 `/api` 开头。

安装走仓库根的 `.npmrc`。npm 源、Node 发行包和其它下载地址的国内替代见 [技术设计.md](./技术设计.md) 第 2.3 节。前端依赖都是纯 JavaScript 包，没有额外的二进制源。

## 3. 主题

Naive UI 负责控件外观。`theme.ts` 里覆盖这些令牌，让默认的蓝白收成纸色：

| 令牌 | 值 |
| --- | --- |
| `common.primaryColor` | `#3d6b58` |
| `common.primaryColorHover` | `#4f7d69` |
| `common.primaryColorPressed` | `#315746` |
| `common.bodyColor` | `#f3f0e8` |
| `common.cardColor` | `#fffcf7` |
| `common.textColorBase` | `#24302c` |
| `common.borderColor` | `#e3d9cc` |
| `common.errorColor` | `#8c4a3a` |
| `common.fontFamily` | `"Avenir Next", "PingFang SC", "Noto Sans SC", sans-serif` |
| `Button.borderRadiusMedium` | `2px` |
| `Input.borderRadius` | `2px` |
| `Card.borderRadius` | `2px` |

页面底色在 `main.css` 里设为 `#f3f0e8`。树卡片上的姓名用衬线：`"Iowan Old Style", Palatino, "Songti SC", "Noto Serif SC", serif`。不从外部字体服务器加载字体。

控件只用这些：

| 场景 | 组件 |
| --- | --- |
| 登录和编辑 | `NForm`、`NFormItem`、`NInput`、`NInputNumber`、`NSelect` |
| 进入、保存、取消、放大缩小 | `NButton` |
| 删除确认 | `NModal` |
| 窄屏上的详情 | `NDrawer` |
| 桌面上的详情容器 | `NCard` |
| 保存成功或失败 | `useMessage` |
| 顶栏 | `NLayoutHeader`，内容区自己排 |

树节点是普通 `button` 加 div，因为 Naive 没有这种卡片。选中时边框改为 `#3d6b58`。

## 4. 路由

| 路径 | 页面 | 条件 |
| --- | --- | --- |
| `/login` | 登录 | 已登录则替换到 `/` |
| `/` | 族谱 | 未登录则替换到 `/login` |

打开某个人用 `/?person=<id>`。新建用 `/?create=1`。两者同时存在时以新建为准。`id` 不是正整数时忽略参数。详情 404 时去掉参数，并用 `useMessage` 提示「找不到这个人」。

## 5. 数据

`api/client.ts` 使用 `fetch`，`credentials: 'include'`。`POST`、`PATCH`、`DELETE` 带 `X-Familytree: 1`。

- 响应 401：清空会话并进入登录页。登录接口自己的 401 留在表单上。
- 响应 204：返回空。
- JSON 错误：读出 `error` 和可选的 `fields`。
- 网络失败：抛出「网络中断，请再试一次」。

`age` 的类型是 `number | null`。前端不根据 `birthText` 再算。

会话 store 的状态是 `unknown | guest | user`。树 store 保存人物字典、亲子、婚姻、详情和折叠集合。折叠集合的键是 `familytree.collapsed`。

`loadTree()` 整体替换 `GET /api/tree` 的结果。`savePerson` 成功后用返回的详情更新面板，再 `loadTree()`。`removePerson` 成功后关掉面板并重新取树。新增且没有父母的人，重新布局后出现在根那一排。

## 6. 登录页

`NCard` 垂直居中，宽度约 22rem。

- 标题「族谱」，衬线
- 一行小字「家族内部使用」
- `NForm`：用户名、密码。密码框用 `NInput` 的 `show-password`
- `NButton` 文案「进入」，提交中改为「正在进入」并禁用
- 失败时 `NFormItem` 的反馈显示接口返回的 `error`

没有注册，没有忘记密码。

## 7. 族谱页

顶栏用 `NLayoutHeader`：左侧「族谱」，中间的姓名/称谓搜索框（选中后打开对应人物并居中），右侧用户名和「退出」。不把「百忍堂 张」写进顶栏。

顶栏之下，画布占满剩余宽度。有 `person` 或 `create` 时，右侧滑出宽 24rem 的 `NDrawer`（`placement="right"`）作面板。没有则画布用满宽。桌面与窄屏当前一致使用右侧抽屉；窄屏底部抽屉是移动端单独适配时再做。

画布角落四个 `NButton`，文字是「放大」「缩小」「回到全图」「新建」。「回到全图」调用 `fitView`，把整棵树适配到视口。首次数据到达与新建首个根人物后自动全图适配；深链 `/?person=id` 与切换选中人物时把对应卡片平滑居中。

## 8. 多棵根怎么排

`layout.ts` 纯函数，输入是树接口的三份数组和折叠集合，输出卡片坐标、折线和画布尺寸。

### 8.1 谁是一棵根

一个人没有父母时，先看他的婚姻：

- 配偶里有人「有父母」，或者配偶会被选成一棵根：他画成那个人的侧卡，自己不是根。
- 夫妻都没有父母：后代更多的那位当根，另一位当侧卡。人数相同则 id 较小的当根。
- 没有配偶，或者配偶也都不构成上面两种：他自己就是根。

种子里的张尔寿没有父母，范氏也没有父母，后代在张尔寿这一侧，所以根是张尔寿，范氏在他身侧。以后新建一个没有父母的人，若也不只是某棵根的配偶，他就成为右边下一棵根。

所有根按 id 升序，从左到右排在同一行，顶部对齐。棵与棵之间水平间隔 80px。不分页，不设「尚未挂到主干」。

### 8.2 一棵根的内部

从这棵根沿子女向下。每个这样走到的人有一张主卡片。

他的配偶若没有自己的主卡片，就画成右侧侧卡，按 `sortOrder` 从左到右。侧卡可以点击。配偶若已经会在别的位置有主卡片，则不再画侧卡。

子女来自 `parentId` 等于他的记录，按 `sortOrder`、再按 `childId`。再按「另一个父母」分组，组的顺序跟随配偶顺序。没有另一个父母的子女放在最后一组。连线从这对配偶的中缝垂下；只有一个父母时从主卡片底部中点垂下。侧卡下面不另排子女。

主卡片有子女时，底部用文字按钮「收起」或「展开」。收起只影响这个人的后代，同一张图上的其他根不动。折叠 id 写入 `familytree.collapsed`。

### 8.3 尺寸与视口

卡片宽度按姓名估算：中文 16px 一字，左右内边距 16px，主卡最小 96px、最大 168px，侧卡最小 80px。只有姓名时高 44px，有第二行时高 64px。

单元宽取「这一排卡片」和「子女单元之和」的较大值。代与代之间 56px，卡片之间 12px，配偶组之间 28px，整图外圈 48px。

第二行有内容才渲染：`birthYear`、`deceased` 为真时的「已卒」、`age` 不是 `null` 时的「N岁」（包括 0）。`age` 为 `null` 时不留空位。卡片里不放称谓和记述。

视口 `overflow: auto`。画布使用 `transform: translate scale`。空白处拖动平移，滚轮以指针为中心缩放，范围 0.4 到 1.8。卡片上的按下不触发平移。缩放数值留在画布组件里，打开面板时树不卸载。

`layout.test.ts` 至少覆盖：

- 张尔寿这种「自己没父母、配偶也没父母、子女挂在自己名下」的人是根，配偶不是另一棵根。
- 两个互不连接、都没有父母的人，得到两棵并排的根，y 相同，x 递增。
- 被折叠的人没有子女坐标，另一棵根的坐标还在。
- 删除父母链接之后，原来的子女会出现在根列表里。

## 9. 详情

详情面板是右侧 `NDrawer`。标题是姓名。右上角 `NButton`：「修改」「关闭」。

字段用描述列表，标签宽 4.5rem：

| 标签 | 来源 |
| --- | --- |
| 称谓 | `kinship` |
| 原名 | `formerName` |
| 小名 | `nickname` |
| 出生 | `birthText` |
| 卒于 | `deathText` |
| 年龄 | `age` 为数字时显示「N岁」；`null` 时整行不出现 |
| 记述 | `narrative`，保留换行 |

值为空的行直接省略，全部为空时显示「暂无记述」。不写「未知」。字段清单与表单共用 `lib/person-fields.ts`。

亲属用三块「父母」「配偶」「子女」。父母和子女旁边的角色按接口里的 `role` 显示为：父亲、继父、母亲、继母、养母、养父。配偶旁边显示婚姻身份原文。行是 `NButton` 的 text 样式，点击后更换 `person` 并重新取详情。某一块没有记录时，连标题也不渲染。

亲属块下方有「添加亲属」按钮：添加子女、添加配偶会预填与当前人物的关系走新建表单；添加父母先创建新人物，保存后再把关系挂回当前人物。

底部「删除」是 `NButton`，`type="error"`、`text`。确认框用 `NModal`，正文：「会去掉此人与父母、配偶、子女的关系。子女仍保留；若不再有父母，会在同一张图上成为新的根。」所有人都可以看到删除按钮，包括每一棵根。

## 10. 编辑

同一块面板换成 `NForm`。新建的标题是「新建人物」。

字段：姓名、称谓、原名、小名、出生、卒于、记述。出生和卒于用 `NInput`，占位「按资料原文填写，例如 1900.2.18 或 正月十九」，不用日期选择器。记述用 `NInput` 的 `textarea`。

父母、配偶各是一组可增删的行：

- `NSelect` 列出除自己以外的人物，按姓名排序。选项多时用组件自带的过滤。这是编辑时选人，族谱页不另做全站搜索。
- 父母的角色用 `NSelect`，六项：父亲、继父、母亲、继母、养母、养父。默认父亲。
- 配偶身份用 `NInput`，占位「妻子、续弦、丈夫」。
- 顺序用 `NInputNumber`。
- 「添加父母」「添加配偶」是 text 按钮。已选过的人从其他行的选项里去掉。

姓名为空时不提交，`NFormItem` 显示「请填写姓名」。保存调用整体替换接口。`fields` 显示在对应表单项下，`error` 用 `useMessage` 的 error。成环的 409 同样用消息提示。

取消：修改时回到详情；新建时关掉面板并去掉 `create`。保存成功后，新建的人把查询参数换成他的 id。若他没有父母，画布上能看到新的一棵根。

## 11. 构建与最低验证

`npm run build` 产出 `web/dist`，由镜像复制到 `/app/static`。

本地先启动 Nest，再 `npm run dev`。最低确认这几步：登录；同一张图上看到张尔寿这一棵；新建一个没有父母的人之后，他出现在旁边成为另一棵根；展开、收起只影响被点的那一支；详情里 `age` 为 `null` 时没有「岁」。
