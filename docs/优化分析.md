# 族谱项目优化分析

> 分析对象：familytree 当前工作区（HEAD `e273baf`）。
> 分析范围：产品、交互体验、技术方案、代码规范、文档一致性。
> 本文只给建议，未修改业务代码。
>
> 基线验证：
> - `cd server && npm test` 通过（Jest 年龄用例 + `node:test` HTTP 用例）。
> - `cd web && npm test` 通过（2 个文件、6 个用例）。
> - `cd web && npm run build` 通过；产物 JS 713.39 kB，gzip 225.89 kB。
> - 当前种子数据 60 人、73 条亲子链接、21 段婚姻；`server/src` 约 1.5k 行，`web/src` 约 2k 行。
> - 额外用临时脚本验证了布局在特定关系下会重复生成同一人物卡片，脚本未写入仓库。

## 0. 范围决策

根据本轮确认，优化范围收敛如下：

| 事项 | 决定 |
| --- | --- |
| 备份与恢复能力 | 本轮不做；同时清理文档中的备份承诺，避免误导 |
| 保存成功 + 刷新失败的重复创建风险 | 本轮修复 |
| 删除影响范围、导出/快照 | 本轮不做 |
| 移动端适配 | 后续单独做，本轮不排期 |
| 画布初始适配、定位与搜索 | 本轮做 |
| 详情面板内直接添加子女/配偶 | 本轮做 |
| 多根布局的重复节点 | 本轮修复 |
| 500 日志、限流代理 IP、保存/加载错误提示 | 本轮做 |
| 测试覆盖、Lint/CI、常量收敛、文件拆分 | 本轮做 |
| 照片、资料来源、导出、角色与审计 | 本轮不做 |

因此，本轮真正要解决的是六类问题：

1. **正确性**：保存成功但刷新失败会诱发重复创建；特殊亲子结构会重复渲染节点。
2. **续修效率**：在详情面板里直接添加子女/配偶，不再从全局新建开始。
3. **找人**：首次进入适配全树、深链/切换人物居中、按姓名搜索定位。
4. **可诊断性**：500 异常留日志；登录限流不再被代理 IP 误伤；加载/保存失败有明确提示。
5. **工程化**：补齐关键测试、Lint/CI、常量收敛、超限文件拆分。
6. **文档清理**：把本轮不做的备份、移动端等承诺从文档中删除或标注为暂不提供。

不建议现在做的架构级改动：引入 Postgres/Redis、拆微服务、实时协作、通用组织架构图组件、多租户和复杂权限。当前“单容器 + SQLite + 纯函数布局”的选择与规模是匹配的。

## 1. 做得好的地方

先明确哪些不要动：

- **领域模型干净**：人物、亲子链接、婚姻三张事实表，没有“主家族”“锚点”字段；根由“有没有父母、是否侧卡”推导，规则集中。见 [people.service.ts](../server/src/people/people.service.ts)。
- **认证方案扎实**：`scrypt` 密码散列、会话令牌只存 SHA-256、Cookie 内 HMAC、HttpOnly + SameSite=Lax、变更请求要求 `X-Familytree` 头。见 [auth.service.ts](../server/src/auth/auth.service.ts)、[token.ts](../server/src/auth/token.ts)。
- **布局是纯函数**：`layout.ts` 不发请求，`graph.ts`、`lines.ts` 职责已拆开，前端测试直接锁行为。
- **迁移纪律**：只追加迁移，不改已发布的 `Init`；启动时自动迁移、引导账号、空库种子，顺序清晰。
- **部署克制**：单容器同时托管页面和 API，非 root 运行、只读根文件系统、SQLite 放卷、WAL + `busy_timeout`。
- **工程约定清楚**：`.agents/AGENTS.md`、`familytree`、`code-style` 三个技能把契约、测试位置、代码风格写得比较具体。
- **代码卫生**：全仓没有 `any`、`console.log`、`TODO/FIXME`；`strict` 打开；没有复制出来的第二套年龄解析。

## 2. 产品与体验（本轮范围）

### 2.1 续修：在详情里直接添加亲属

当前详情面板只有“修改”“关闭”两个动作，关系必须回到全局“新建”里手工选人。见 [person-panel.vue](../web/src/components/person-panel.vue#L145-L147) 和 [person-form.vue](../web/src/components/person-form.vue#L170-L188)。

这是“续修族谱”最高频的动作，却要求用户：

```text
记下当前人物 → 新建 → 填姓名性别 → 在父母/配偶下拉里重新找到他 → 选角色 → 保存
```

建议增加上下文动作：

| 动作 | 预填内容 | 请求方式 |
| --- | --- | --- |
| 添加子女 | `parents: [{ personId: 当前人, role }]` | 一次 `POST /api/persons` |
| 添加配偶 | `marriages: [{ personId: 当前人, label }]` | 一次 `POST /api/persons` |
| 添加父/母 | 新建人物后，把新人物加入当前人的 `parents` | 前端串联创建 + `PATCH`，或后续加一个原子接口 |

这样后端契约不变，只是把“找人”从全局下拉变成上下文预填。现有的关系选择器保留，作为“关联已有的人”的高级入口。

验收：从某人详情点击“添加子女”，表单已带上当前人作为父亲/母亲；保存后新人立即挂在该人物下面，无需手工选择父母。

### 2.2 找人：初始适配、定位与搜索

当前画布存在的问题：

- **初始视口不适配全树**：Vue Flow 默认视口在左上角，树很宽时用户第一次进入只能看到左侧一部分。建议首次加载后调用 `fitView`。
- **“回到全图”名不副实**：`canvas-tools.vue` 当前执行 `setViewport({ x: 0, y: 0, zoom: 1 })`，只是回到左上角、100% 缩放，并不会把整棵树装进视口。见 [canvas-tools.vue](../web/src/components/canvas-tools.vue#L12-L14)。建议改成 `fitView` 并留边距。
- **深链不居中**：打开 `/?person=<id>` 时只请求详情，不会把该人物滚到视野中。分享链接或从关系列表跳转后，用户可能看不到当前选中的人。
- **新建的人可能在视野外**：新根追加在右侧；没有 `fitView` 时，用户保存后看不到他，以为没成功。
- **没有搜索**：需求第一版明确不做按姓名搜索，但本轮已确认需要。建议在顶栏加一个按姓名/称谓过滤的搜索框，选中后居中并打开详情；数据已经全量在前端，不需要新接口。

验收：打开宽树能看到全貌；`/?person=id` 打开后该人居中；输入姓名能跳转并高亮选中。

### 2.3 本轮不展开的体验项

以下已经发现，但不属于本轮范围，保留备查：

- 桌面详情抽屉的透明遮罩会拦截画布点击，点击另一个人会先关闭抽屉；后续做“桌面非模态侧栏”时一起处理。
- 移动端仍是右侧抽屉，设计文档要求窄屏底部抽屉；关系行固定四列在窄屏会溢出。等移动端单独适配时处理。
- 配偶的 `marriage.label`（续弦、继母等）录入了但详情不展示，当前只按性别显示“妻子/丈夫”。
- 父母/配偶每行裸暴露 `sortOrder` 数字，且后端只取优先级最高那一行的值，语义不直观。
- 空字段当前被过滤，全部为空时显示“暂无记述”，与 `reference.md` 的“空字段留标签、右边空白”不一致。
- 编辑中关闭抽屉、取消、浏览器后退或 401 跳登录都会丢失未保存内容。
- 登录失败错误显示在“用户名”表单项下，密码错误看起来像用户名错误。
- 画布性别只用颜色区分，已卒标记只有 `title`，键盘平移/缩放不完整，`setCenter` 固定 250ms 动画没有尊重 `prefers-reduced-motion`。

## 3. 技术方案（本轮范围）

### 3.1 保存成功与树刷新解耦

当前 `savePerson` 先保存、设置详情，再 `await loadTree()`：

```text
POST/PATCH 成功 → this.detail = detail → await loadTree()
```

如果 `loadTree` 失败，表单的 `catch` 会提示“网络中断”，但人物其实已经创建成功；用户再次点保存就会 POST 出第二个人。见 [tree.ts](../web/src/stores/tree.ts#L40-L48)、[person-form.vue](../web/src/components/person-form.vue#L87-L138)。

建议改成两个用户可见的结果：

```text
保存成功 → 先视为成功（返回详情、关闭/更新表单）
刷新树失败 → 只提示“已保存，但列表刷新失败，请手动刷新”，不把保存标成失败
```

技术实现可以是：`savePerson` 只负责保存并返回详情；调用方在保存成功后 `emit('saved')`，再异步刷新；刷新失败单独 `message.warning`。同时给 `/api/tree` 加一次重试或“重新加载”按钮。

验收：模拟 `loadTree` 失败后重试保存，不会产生第二个人；用户明确知道“已保存，只是列表没刷新”。

### 3.2 多根布局的重复节点

已验证的复现条件：一个孩子同时有父亲和母亲，但父母之间没有婚姻记录，且两人都没有父母。此时父亲和母亲各自成为一棵根，`layoutUnit` 会从两棵根分别走到这个孩子，生成两张同 id 卡片：

```text
persons: 父(1), 母(2), 子(3)
parent_links: 3→1(father), 3→2(mother)
marriages: []
roots: [1, 2]
cards: 1@48,48  3@48,152  2@240,48  3@240,152
```

Vue Flow 节点 id 都是 `"3"`，会出现节点覆盖/边指向不确定。更一般地，一个没有父母的配偶被两棵根共享时，也会在两行侧卡里重复出现。根因是 `layout` 只保证侧卡不重复，没有全局记录“这个人已经被排过”。见 [layout.ts](../web/src/lib/layout.ts#L89-L285)、[layout.test.ts](../web/test/layout.test.ts)。

建议：

- 用一个全局 `claimed` 集合，按根的顺序首次认领人物；已被其他根排过的人不再生成卡片；
- 或者在布局前先做“人物 → 主根”的归属计算，保证每人只属于一棵根；
- 补回归测试，覆盖“父母未结婚但同为一个孩子的父母”和“两棵根共享配偶”两种结构。

验收：上述两种结构都只生成一张人物卡片，Vue Flow 节点 id 唯一。

### 3.3 错误与可诊断性

**500 异常没有日志。** `ApiExceptionFilter` 捕获所有异常，返回 `{ error: '服务暂时不可用' }`，但没有 `Logger.error`，堆栈完全丢失。见 [api-exception.filter.ts](../server/src/api-exception.filter.ts#L25-L26)。建议记录 method、path、异常堆栈；响应体仍保持通用文案。

**限流可能把所有用户算成同一个 IP。** `clientIp()` 只有在直连地址命中 `127.0.0.1/::1/TRUSTED_PROXY` 时才读 `X-Forwarded-For`。Docker 里通过宿主网关或边缘 Nginx 访问时，容器看到的对端可能不是回环地址；一旦如此，所有用户共享一个计数桶，8 次失败就会把全站锁 10 分钟。`docker/README.md` 的 FAQ 也提到了这一点。见 [auth.service.ts](../server/src/auth/auth.service.ts#L54-L67)。建议：

- 支持 CIDR，而不只是精确 IP；（已评估后放弃：单容器直出部署下收益小、增加 auth 复杂度，维持精确 IP 匹配）
- 或按“用户名 + IP”组合计数，并给共享出口更高阈值；
- 部署时明确验证日志里的对端地址。

**加载/保存错误提示不完整。**

- `tree-view.vue` 的 `onMounted` 直接 `void tree.loadTree()`，没有 `catch`；网络失败或 500 时画布为空，还会显示“还没有人物”，用户无法区分“空库”和“加载失败”。见 [tree-view.vue](../web/src/views/tree-view.vue#L72-L74)。
- 详情 watcher 只处理 404，500 或网络错误被 `catch` 后静默吞掉，面板空白。
- `client.ts` 的 `JSON.parse(text)` 没有 `try/catch`；反向代理返回 502 HTML 时会抛 `SyntaxError`，调用方只能显示“网络中断”。见 [client.ts](../web/src/api/client.ts#L33-L43)。

建议补统一的加载态、错误态和重试入口；非 JSON 响应也转成 `ApiError`，让页面能显示可读提示。

验收：断网、500、502 HTML 三种情况下都有明确提示和重试；500 日志可定位到请求和堆栈。

## 4. 代码规范与工程化（本轮范围）

整体代码质量在同类项目中偏上：严格 TS、无 `any`、无调试残留、命名清楚。以下与本轮决策直接相关。

### 4.1 测试覆盖

当前测试覆盖的是“最容易出错且最纯”的部分：年龄、根判定、布局、`toFlow`。缺口：

- 后端缺少：缺少 `X-Familytree` 的 403、详情 404、引用不存在/指向自己/重复父母或婚姻的 422、会话过期、种子空库/非空库、静态托管。
- 前端缺少：`person-form` 的校验与提交、`api/client` 的 204/401/非 JSON 响应、`session`/`tree` store、路由守卫、详情面板的配偶身份标签。
- 没有组件级或端到端测试；本轮新增的“保存/刷新分离”“多根去重”“搜索结果”都需要回归用例。
- 后端同时使用 Jest（`age.spec.ts`）和 `node:test`（`app.spec.ts`）两个 runner，且 `app.spec.ts` 手工重复了 `main.ts` 的 `ValidationPipe` 和异常过滤器配置。测试通过不代表生产 wiring 通过。

建议抽出 `configureApp(app)`，让 `main.ts` 和 HTTP 测试共用；新增接口补成功 + 失败两条用例；修 bug 先补能复现的用例。

见 [app.spec.ts](../server/test/app.spec.ts#L28-L37)、[jest.config.js](../server/jest.config.js)、[main.ts](../server/src/main.ts#L21-L28)。

### 4.2 Lint、CI 与最小门禁

当前没有 ESLint/Prettier 配置，也没有 CI。风格靠 `.agents` 文档和人工评审维持。建议加最小集：

- ESLint（`@typescript-eslint` + `eslint-plugin-vue`）、Prettier；
- `tsc --noEmit`、`server npm test`、`web npm test`、`web npm run build` 作为 CI 关卡；
- 两个 `package.json` 声明 `engines`，避免 Node 版本漂移。

### 4.3 常量收敛

- **卡片尺寸有三份**：`layout.ts` 的 `CARD_W/CARD_H`、`flow.ts` 的 `node.width ?? 112`/`height ?? 48`、测试里的 `112`/`48`。建议从 `layout.ts` 导出常量，`flow.ts` 和测试引用同一份。
- **主题色散落在 22 处**：`#3d6b58`、`#9c4036`、`#a89884`、`#e4d8c8`、`#fffcf7` 等同时出现在 `theme.ts`、组件 `<style>` 和 `flow.ts` 的内联样式里。建议收成 CSS 变量或一个 `tokens.ts`。
- **字段清单有两份**：`person-panel.vue` 的 `fields` 和 `person-form.vue` 的一组 `n-form-item` 各自维护。加字段时容易漏；可以用一个字段描述数组驱动展示，但不要为此引入复杂表单框架。

### 4.4 文件与函数拆分

`code-style` 规定单文件约 300 行、单函数约 50 行、参数 ≤ 4 个。当前几处已经贴近或超过：

| 位置 | 现状 | 规则 | 建议 |
| --- | --- | --- | --- |
| [layout.ts](../web/src/lib/layout.ts#L162-L262) 的 `layoutUnit` | 约 100 行 | 函数约 50 行 | 抽出“排一行卡片”“排子女组”“生成折叠节点”三个内聚函数 |
| [layout.ts](../web/src/lib/layout.ts#L89-L285) 的 `layout` | 约 197 行（含内部闭包） | 函数约 50 行 | 把 `collectRow`/`groupChildren` 移到模块级，输入输出显式化 |
| [people.service.ts](../server/src/people/people.service.ts#L175-L242) 的 `replaceRelations` | 约 68 行 | 函数约 50 行 | 拆出“重复校验”“引用存在性校验”“写入链接” |
| [people.service.ts](../server/src/people/people.service.ts) | 298 行 | 文件约 300 行 | 再加一个关系规则就会超限；可拆读侧/写侧 |
| [layout.ts](../web/src/lib/layout.ts) | 285 行 | 文件约 300 行 | 与上一条同属“无余量”状态 |
| [person-panel.vue](../web/src/components/person-panel.vue) | 284 行 | 文件约 300 行 | 尚未违规但余量很小；加“添亲属”动作前按展示、表单编排、动作拆分 |
| [lines.ts](../web/src/lib/lines.ts#L52-L62) 的 `bloodLine` | 7 个参数 | 参数 ≤ 4 | 收成参数对象 |

拆分以职责为边界，不为行数机械切割。上面的位置都有自然缝隙。

### 4.5 其他规范项

- `age.ts` 的 `YEAR_RE` 已经限定 `18xx/19xx/20xx`，`readYear` 里再判断 `year < 1800 || year > 2099` 永远不会命中，可以删掉。见 [age.ts](../server/src/people/age.ts#L13-L27)。
- `AuthService.secret()` 的长度检查与启动时的 `applyDefaults` 重复。作为安全边界可以保留，但要明确它是“防御性冗余”。
- `server/test/env.ts` 被 Jest 作为 `setupFiles` 使用，不是死代码；但它对 `age.spec.ts` 并不必要，且与 `app.spec.ts` 的环境设置有重复。统一 runner 后可以删掉这层间接。
- 没有根 README、`server/.env.example`。建议补一份简短的根 README（本地启动、环境变量、测试、部署入口）和本地环境变量模板；这是开发者体验，不是业务功能。

## 5. 本轮不展开的技术项

以下问题真实存在，但根据本轮范围暂不处理，避免与上面的工作混在一起：

- **备份/恢复**：文档承诺 `src/backup.ts` 和 `node dist/backup.js`，当前源码不存在。本轮不实现备份，但必须清理文档中的承诺和 `entrypoint.sh` 的 `/data/backups` 说法，避免用户按文档操作失败。
- **删除安全**：删除人物是硬删除；本轮不做影响预览、导出快照或软删除。
- **移动端**：右侧抽屉、底部抽屉差异、关系行窄屏溢出，整体后移。
- **桌面详情形态**：透明遮罩拦截画布点击，非模态侧栏后移。
- **配偶身份、`sortOrder`、空字段展示、未保存提醒、登录错误位置、可访问性**：已记录，本轮不排期。
- **配置读取顺序**：`app.module.ts` 在模块加载时读取 `process.env.STATIC_DIR`，而 `main.ts` 在 `bootstrap()` 才 `loadEnvFile()`；从 `.env` 读取的 `STATIC_DIR` 不会被 `AppModule` 看到。Docker 用真实环境变量，生产不受影响；本地静态托管会失效。
- **详情多次查询没有事务**：并发修改时可能读到半更新状态；当前单用户、SQLite 同步驱动下概率低。
- **数据库约束弱于领域规则**：一个子女可以有多条 `father` 链接；父亲链接可以指向 `sex='female'` 的人；婚姻没有结束/离异状态。
- **安全加固**：账号枚举时序差异、密码最小长度、过期会话清理、HSTS/CSP。
- **性能与包体**：当前 600 人合成数据布局约 6ms，无需优化；前端 713 kB 可按路由拆分，但不是本轮重点。
- **照片、资料来源、导出、角色与审计**：不展开。

## 7. 实施顺序建议

不按时间估算，只给先后关系。

### 第一批：正确性

| 事项 | 验收 |
| --- | --- |
| 保存成功与树刷新解耦 | 模拟 `loadTree` 失败，重试保存不会产生第二个人；提示区分“已保存/刷新失败” |
| 多根布局去重 | 父母未结婚、两棵根共享配偶两种结构均只生成一张卡片；补回归测试 |
| 500 异常日志 | 人为触发 500，日志有 method/path/stack，响应体仍是通用文案 |

### 第二批：核心体验

| 事项 | 验收 |
| --- | --- |
| 首次加载/新建后 `fitView`，深链与切换人物居中 | 打开宽树能看到全貌；`/?person=id` 打开后该人居中 |
| 搜索与定位 | 输入姓名/称谓能跳转、居中并打开详情；无结果有提示 |
| 详情内“添加子女/配偶/父母” | 从某人详情创建后自动挂上关系，不需要全局下拉找人 |
| 加载/保存错误提示与非 JSON 响应处理 | 断网、500、502 HTML 都有明确提示和重试 |

### 第三批：工程化

| 事项 | 验收 |
| --- | --- |
| 补关键后端/前端测试 | 403/404/422/会话过期、表单校验、client 非 JSON、store 竞态均有覆盖 |
| ESLint/Prettier/CI，抽取 `configureApp` | CI 上 lint + 两边测试 + 构建全绿；测试不再复制生产 wiring |
| 常量收敛与文件拆分 | 卡片尺寸/主题色/字段清单只有一份来源；目标函数回到 50 行、参数 ≤ 4 |
| 限流代理 IP 配置与验证 | 边缘代理下不同用户使用不同计数桶；日志能核对对端地址 |

## 8. 不建议现在做的事

- 不要因为“以后可能多人”就引入角色权限、审计表、多租户和复杂会话管理。
- 不要把 SQLite 换成 Postgres，或把单容器拆成前后端两个服务。
- 不要为了“树更好看”改成可拖拽的组织架构图，现有“多根并排、配偶侧卡、折叠”是产品差异点。
- 不要引入通用表单引擎或把字段配置做得过度抽象。
- 不要为了追求 100% 测试覆盖去镜像实现；优先覆盖契约、边界和数据安全路径。
